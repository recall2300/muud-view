## 2026-11-24 — M4 클립보드 확장 ✅

- **버그 수정:** egui가 `Ctrl+C`·`Ctrl+Insert`·`Shift+Insert`·`Shift+Delete`를 텍스트용 복사/붙여넣기로 가로채서, v0.1의 `Ctrl+C`와 M3의 보관함 키 일부가 실제로는 동작하지 않았음 → 가로채기를 끄고 직접 처리
- `Ctrl+C`: 이미지 + 파일을 한 번에 클립보드에 (Windows `CF_DIB` + `CF_HDROP`). 탐색기에 붙여넣으면 파일, 채팅·문서에 붙여넣으면 그림
- 큰 이미지(GPU 한도로 축소된 경우)는 원본을 다시 디코딩해서 원본 해상도로 복사. EXIF 방향 반영
- `Ctrl+Alt+C`: 긴 변 1600px로 줄여서 복사 (메신저용)
- `Ctrl+V`: 클립보드에 파일이 있으면 그 파일을 열고, 그림이 있으면 바로 보여줌 (캡처 화면 확인용)
- 복사는 백그라운드에서 처리하고 끝나면 알림 (큰 사진에서 화면이 멈추지 않게)
- 테스트 +4 (DIB 바이트 구조, DROPFILES 구조·한글 경로, 새 키)

## 2026-11-24 — M3 사진보관함 + 되돌리기 ✅

- `Insert` 보관함 1 복사 · `Ctrl+Insert` 보관함 1로 이동 · `Shift+Insert` 보관함 2 복사 · `Alt+1~9` 보관함 1~9 복사
- 기본 위치 `사진\muud-view\1` … `\9` (Windows 알려진 폴더 API로 찾아서 OneDrive로 옮겨진 사진 폴더도 따라감). 경로 변경은 M8 설정 화면에서
- 같은 이름이 있으면 `사진 (2).jpg`, `사진 (3).jpg` …, 다른 드라이브로 이동도 지원(복사 후 삭제)
- `Ctrl+Z` 되돌리기 (최근 50개): 복사 → 사본 삭제, 이동 → 원래 자리로, 휴지통 → 휴지통에서 복원. 원래 순서 위치로 목록에 다시 넣음
- 라이선스 검사가 `dirs` 크레이트의 MPL-2.0 의존성을 잡아내서 제거하고 Windows API를 직접 호출하도록 변경
- 테스트 +7 (이름 충돌, 복사·이동, 경로 결정, 되돌리기, 실패 시 유지, 50개 제한, 보관함 키)

## 2026-11-24 — M2 하단 바 + 진행 바 ✅

- 하단 바: `PREV` `NEXT` · `012 / 120` · 진행 트랙 · `−` `1:1` `+` `FIT` · `ROT` `FULL` · `INFO` `PIN`
- 진행 트랙: 점선 위로 지나온 구간 실선 + 현재 위치 점, 클릭·드래그로 이동, 마우스를 올리면 번호·파일명 말풍선
- 자동 숨김: 화면 위·아래 96pt 안으로 마우스가 오면 0.18초 페이드 인, 벗어나고 1.4초 뒤 사라짐. 바가 이미지 위에 떠서 화면이 흔들리지 않음
- 고정: `` ` `` 상단(기본 고정), `~` 하단(기본 자동 숨김), 설정에 저장. 전체화면에서는 둘 다 자동 숨김
- 하단 바가 숨겨져 있으면 맨 아래 2px 진행선
- 테스트 +4 (트랙 위치 ↔ 번호 변환, 고정 키)

## 2026-11-24 — M1 구조 정리 + 빠른 JPEG ✅

- `app.rs`(1,700줄)를 `app/` · `core/` · `ui/` · `platform/`으로 분리
- `core::library::Library`: 파일 목록·위치·캐시·미리 읽기를 UI와 분리, 테스트 5개 추가 (넘김 끝 처리, 진행 방향 미리 읽기, 제거·복원, 캐시 비우기)
- JPEG 빠른 경로: zune-jpeg가 화면 버퍼에 바로 디코딩 → RGB→RGBA·프리멀티플라이 단계 제거
- EXIF 방향은 픽셀을 돌리지 않고 그릴 때 적용 (사용자 회전과 합성), 복사할 때만 픽셀 회전
- 디코딩 스레드: 코어 수 − 1 (2~7개)
- 측정 (같은 2코어 서버, 32.5MP·18MB JPEG): **530ms → 369ms (−30%)**
- 테스트 28 → 38개
