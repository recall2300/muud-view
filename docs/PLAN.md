# muud view — 구현 계획

[ROADMAP.md](ROADMAP.md)의 모든 항목을 실제로 만드는 순서와 방법입니다.
진행 상황은 [PROGRESS.md](PROGRESS.md)에 마일스톤마다 기록합니다.

## 원칙

1. **클린룸** — 동작은 공개 문서 기준으로 맞추고, 다른 뷰어의 바이너리·코드·리소스는 쓰지 않는다.
2. **허용 라이선스만** — MIT / Apache-2.0 / BSD / Zlib / OFL / IJG 등. `cargo deny`가 막는다. MPL·LGPL·GPL은 쓰지 않는다. 정적 링크하는 C 라이브러리(libjpeg-turbo)는 `cargo deny`가 보지 못하므로 라이선스 전문을 `assets/licenses/`에 두고 릴리스에 함께 넣는다.
3. **네트워크 없음** — 통신 코드를 넣지 않는다. 업데이트 확인도 "누르면 Releases 페이지를 연다" 수준까지만.
4. **마일스톤마다 쓸 수 있는 상태** — 각 마일스톤은 CI 통과 + 테스트 + 기록 후 `main`에 올린다. 버전 단위로 릴리스.
5. **테스트 우선** — UI가 아닌 로직(목록·캐시·보관함·키맵·되돌리기·레지스트리 키 구성)은 egui 없이 단위 테스트한다. UI는 가상 화면 스크린샷으로 확인한다.

## 구조 (M1 이후 목표)

```
src/
  main.rs            진입점, 창 하나로 열기 분기
  app/               상태와 흐름
    mod.rs           MuudApp, 프레임 흐름
    commands.rs      Cmd 실행
    library.rs       파일 목록·현재 위치·캐시·미리 읽기 (egui 없이 테스트)
  core/
    loader.rs        백그라운드 디코딩 (파일 읽기 / 디코딩 단계 분리)
    decode.rs        포맷별 디코딩, JPEG 전용 빠른 경로
    view.rs          확대·이동·회전 계산
    keymap.rs        동작 ↔ 키·마우스 매핑, 사용자 설정 병합
    settings.rs      설정 저장 (일반 / 포터블 모드)
    photo_folders.rs 사진보관함 복사·이동·이름 충돌
    history.rs       되돌리기 (이동·휴지통)
    exif_info.rs, folder.rs
  ui/
    theme.rs         스펙 시트 스타일
    top_bar.rs, bottom_bar.rs, canvas.rs, info_panel.rs, overlays.rs, settings_window.rs
  platform/
    mod.rs           공통 인터페이스
    windows.rs       레지스트리·셸·클립보드 파일·창 하나로 열기 (Windows 전용)
```

## 검증 방법

- `cargo test` — 로직 단위 테스트 (목표: 마일스톤마다 추가)
- `cargo clippy -D warnings`, `cargo fmt --check`, `cargo deny check licenses`
- GitHub Actions `windows-latest`에서 빌드·테스트 (Windows 전용 코드는 여기서만 컴파일됨)
- 가상 화면 스크린샷(`MUUD_SCREENSHOT`, `MUUD_SIZE`, `MUUD_SHOW`)으로 UI 확인
- Windows 실물 확인이 필요한 항목은 `docs/CHECKLIST.md`에 모아 릴리스 전에 점검
